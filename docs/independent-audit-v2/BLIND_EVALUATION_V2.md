## 1. Cold Discovery & Plain-English Ergonomics Log

### First 60 Seconds: Calmness, Orientation & Mental Model
Approaching `http://localhost:5173` cold at `1440×900` as an on-call L2/L3 MSP cloud engineer, the landing screen (`#INC-4092 · Contoso Finance · AVD, License & NSG Drift`) immediately establishes a clear two-column mental model:
- **Left Pane (40% width — Ticket & Triage Plan):** Displays the incoming PSA ticket (`#INC-4092`), a plain-English **Summary & Resolution Plan** with 3 numbered remediation steps, a cross-tenant alert banner (`🌐 3 other client tenants have this same misconfiguration · [Review & Fix All 3 →]`), the customer's raw ticket body enriched with color-coded entity pills, an attached user screenshot (`contoso-avd-error-screenshot.png`), and collapsible context accordions (`Enriched Tenant Objects (11)`, `Contract #CNT-2026-884`, `Infrastructure spec`, `Timeline`).
- **Right Pane (60% width — Live Tenant Diagnostic Canvas):** Displays a tenant breadcrumb (`Contoso Finance › c4a8shili.onmicrosoft.com › #INC-4092 · 3 cards`), a 5-step **Incident Timeline** bar (`Before Issue (07:46)` → `Config Changed (07:50)` → `First Error (07:58)` → `Now (Active)` → `After Fix (Preview)`), and **three collapsed diagnostic cards by default**:
  1. `License Pool & Assignment · SG-Contoso-Finance-AVD` (`Action Needed` / `Warning`)
  2. `Sign-In History & Conditional Access` (`Action Needed`)
  3. `AVD Host Pool, NSG & Azure Policy` (`Action Needed`)

### What Delighted a Skeptical L2/L3 Sysadmin
1. **Default-Collapsed Progressive Disclosure:** Unlike typical "single-pane-of-glass" MSP dashboards that dump five scrolling tables onto the screen at once, starting with the three right-pane cards collapsed makes the `1440×900` landing state feel calm, scannable, and high-signal. Each collapsed card states the exact blast radius (`3/5 users in SG-Contoso-Finance-AVD drifted: current SPE_E3 vs expected SPE_E5`) and offers a direct primary CTA alongside `Expand Details`.
2. **Plain-English Tab & Control Renaming in the Approval Drawer:** Inside the **Review & Approve Fix** drawer (`v2-shot-08.png` – `v2-shot-10.png`), the four top-level tabs are named in everyday sysadmin language—**`Scripts & Changes`**, **`Safety Checks & Undo`**, **`Other Clients (3)`**, and **`Customer Note & Docs`**—and fit on a single horizontal row without clipping.
3. **Screenshot OCR to Sign-In Log Correlation (`v2-shot-07.png`):** Clicking **`Scan Screenshot for Error Code & Timestamp`** on `contoso-avd-error-screenshot.png` extracts `AADSTS53003`, correlation ID `7f8a9d12-4410-4b9e-9c1a-00155d8a4201`, and device `CONTOSO-LT-0471`, then automatically expands the `Sign-In History & Conditional Access` card and highlights the exact `08:04:10Z` failure row with a purple ring and `👁 vision match` pill.
4. **Free-Text Selection to Custom Diagnostic Card (`v2-shot-07.png`):** Highlighting `"vendor opened 'temporary RDP' on the host pool NSG"` inside the ticket body pops up a floating selection toolbar (`Generate Context UI for "vendor opened 'temporary RDP'…"` with view mode switches `Dashboard`, `Full Card`, `Compare`, `Blast Radius`) that synthesizes a dedicated NSG drift card above the standard canvas cards.
5. **Intune Tattooed Registry Awareness (`v2-shot-12.png`):** On `#INC-4099` (`Fabrikam Legal · Intune BitLocker & Compliance Drift`), the `Setting-Level Drift Diff` table explicitly flags `HKLM\SOFTWARE\Policies\Microsoft\FVE\EncryptionMethodWithXtsOs` with an amber **`tattooed on unassign`** pill—recognizing that legacy Intune `DeviceConfiguration` BitLocker profiles tattoo registry keys that must be scrubbed via a Proactive Remediation script (`Detect.ps1` / `Remediate.ps1`).

### What Still Felt Confusing, Hidden, or Jargon-Heavy During Cold Discovery
1. **Internal AI/Router Jargon Leaking into Admin Surfaces:**
   - Hovering an inline entity pill (`v2-shot-03.png`) shows a footer inside the popover reading `⚙ Tier 1A · Modal open weights   1 ms`.
   - Generating a custom card from selected ticket text (`v2-shot-07.png`) pops a bottom-left toast reading `1 rows · muse-spark-1.3 · 3255 tokens · 2767 ms · ptr://inc-4092/selection/151ig4j`.
   - Opening the approval drawer briefly flashes a progress rail (`Preparing fix scripts & running safety checks`) exposing `+0 ms mcp:start`, `+747 ms plan:start Tier 3A · muse-wonder-1.0 planning remediation`.
   - The `License Pool & Assignment` card header (`v2-shot-05.png`) displays `pool: fixture` on the far right of the sub-tab bar.
2. **Ambiguous Git/PR Controls in the Drawer Footer (`v2-shot-08.png`):** The footer shows a 2-way segmented switch on the left (`⚡ Apply Live Now (+ Sync Git)` vs. `🔀 Create GitHub PR Only`) AND a separate `☐ Open GitHub PR` checkbox on the right, above a third green button (`⚡ Apply Fix Now`). An admin has to pause and guess how `+ Sync Git`, `Create GitHub PR Only`, and `Open GitHub PR` interact.
3. **`Test Auto-Rollback` Checkbox Does Not Update Primary Button Label (`v2-shot-10.png`):** Ticking `☑ Test Auto-Rollback` in the drawer footer leaves the primary green CTA button labeled **`⚡ Apply Fix Now`**, creating anxiety over whether clicking it will run a safe rollback drill or execute a live production change.

## 3. Part B — Post-Screenshot Text, Script & Technical Audit

Following Phase 2, we audited the live HTTP responses from `http://localhost:4000`, the persisted remediation bundles in `data/remediations/`, and the TypeScript source across `apps/orchestrator/src/` and `apps/web/src/`.

### 3.1 M365 / Entra / Intune / Azure Domain & Script Accuracy

#### A. `#INC-4092` (Contoso Finance — Group Licensing, Conditional Access & Azure NSG Drift)
- **What Is Production-Grade:**
  - Correctly models Entra group-based licensing in [`data/remediations/rem-mvr3ouhj-gwd2.json`](file:///c:/dev/contextpane/data/remediations/rem-mvr3ouhj-gwd2.json#L12) and [`remediate.ts`](file:///c:/dev/contextpane/apps/orchestrator/src/local/remediate.ts#L164-L181): instead of calling `Set-MgUserLicense` directly on group-licensed users (which fails with `LicenseAssignmentCannotBeModified` on group-assigned SKUs), it removes the user from the legacy E3 group (`Remove-MgGroupMemberByRef`), ensures membership in the E5 group (`New-MgGroupMemberByRef`), and forces license recalculation (`Invoke-MgLicenseUser`).
  - Checks and populates `UsageLocation` (`CH`) before license reprocessing.
  - Wraps every mutating cmdlet in `$PSCmdlet.ShouldProcess(...)` with `[CmdletBinding(SupportsShouldProcess)]` and validates `Get-MgContext` tenant alignment.
  - Zero `<placeholder>` tokens in the persisted bundle (`rem-mvr3ouhj-gwd2.json`); all group, user, and policy IDs are valid UUIDs.
- **Technical Domain Flaws Found in Code/Scripts:**
  1. **Deterministic Fallback Hardcodes Non-GUID Group Strings (`remediate.ts:L154-L176`):** In [`apps/orchestrator/src/local/remediate.ts`](file:///c:/dev/contextpane/apps/orchestrator/src/local/remediate.ts#L154-L176), the deterministic template `contosoTicket()` sets `[string]$LegacyGroupId = "sg-contoso-finance-legacy-01"` and calls `Remove-MgGroupMemberByRef -GroupId "sg-contoso-finance-legacy-01"` and `New-MgGroupMemberByRef -GroupId "sg-contoso-finance-avd-01"` (ignoring the parameters and passing display-slug strings instead of Entra Group ObjectId GUIDs, whereas `graphPatch` at line 209 uses the real UUIDs from `GROUP_IDS`).
  2. **Undo Script Passes UPNs to `Remove-MgGroupMemberByRef -DirectoryObjectId` (`formal-verifier.ts:L556-L561`):** In the generated `1-Click Undo Script` (visible in `v2-shot-10.png` and defined in [`formal-verifier.ts`](file:///c:/dev/contextpane/apps/orchestrator/src/local/formal-verifier.ts#L556-L561)), the rollback calls:
     ```powershell
     Remove-MgGroupMemberByRef -GroupId 'a1b2c3d4-e5f6-4a5b-8c9d-0e1f2a3b4c5d' -DirectoryObjectId 'lynne.robins.contoso@c4a8shili.onmicrosoft.com'
     ```
     Against live Microsoft Graph (`DELETE /v1.0/groups/{id}/members/{directoryObjectId}/$ref`), `-DirectoryObjectId` **must be a GUID** (`d51d07ea-ab4c-4e42-a679-06c102f0589d`), not a UPN. Passing a UPN in the `$ref` URL path throws `Request_BadRequest`.
  3. **Undo Script Targets Wrong Conditional Access Policy GUID:** The forward script and Graph patch target Conditional Access policy `d09ae604-4c06-4769-ad01-20ec8efa18ad`, but the Undo script in `formal-verifier.ts` targets `d09ae604-9c1e-4b9c-9a5d-000000000001`.
  4. **Undo Script Re-Opens Port 3389 to `*`:** The Undo script re-adds `Allow-Temp-RDP-Diagnostic-Drift` (`Inbound Tcp 3389 from *`). While mathematically "inverse ($f^{-1}$)", no MSP would ever want a 1-click undo script to re-open an unauthenticated internet-facing RDP hole on an AVD host pool NSG.

#### B. `#INC-4099` (Fabrikam Legal — Intune BitLocker Conflict & Tattooed Registry Keys)
- **What Is Production-Grade:**
  - Accurately models the real-world Windows 11 Intune BitLocker conflict (`0x87D1FDE8`) between an Endpoint Security Disk Encryption baseline (`XTS-AES 256-bit`, silent) and a legacy `DeviceConfiguration` profile (`XTS-AES 128-bit`, prompt).
  - Unassigns the legacy profile via `POST /v1.0/deviceManagement/deviceConfigurations/{id}/assign` with `{ assignments: [] }`, deploys a Base64-encoded Intune Proactive Remediation (`New-MgBetaDeviceManagementDeviceHealthScript`) to scrub the tattooed `HKLM:\SOFTWARE\Policies\Microsoft\FVE` values (`EncryptionMethodWithXtsOs`, `AllowWarningForOtherDiskEncryption`), and triggers `Sync-MgDeviceManagementManagedDevice` across all 6 devices (`rem-mvr3pbkq-hsap.json`).
- **Technical Domain Flaws Found in Code/Scripts:**
  1. **Target Group Name Mismatch (`SG-Fabrikam-Win11-Devices` vs. `SG-Fabrikam-Legal-Workstations`):** The ticket and Step 1 unassign the conflicting profile from `SG-Fabrikam-Win11-Devices`, while Step 2 assigns the Proactive Remediation registry scrubber to `SG-Fabrikam-Legal-Workstations` (both mapped to the same UUID `d4e5f6a7-b8c9-4d5e-8f0a-1b2c3d4e5f6a` in [`remediate.ts:L72-L73`](file:///c:/dev/contextpane/apps/orchestrator/src/local/remediate.ts#L72-L73), which is confusing when reading the script).
  2. **Graph JSON Preview vs. Actual Graph Schema (`remediate.ts:L584-L594`):** In the `Graph API JSON` preview tab (`rem-mvr3pbkq-hsap.json:L14`), the `POST /beta/deviceManagement/deviceHealthScripts` body includes convenience display fields `"targetRegistryKey"`, `"assignedToGroupId"`, and `"assignedToGroupName"`, which are not valid properties on the Microsoft Graph `deviceHealthScript` resource type (whereas the PowerShell script at lines 261–273 properly uses `detectionScriptContent`, `remediationScriptContent`, and the `/assign` action endpoint).
