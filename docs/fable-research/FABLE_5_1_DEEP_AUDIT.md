# FABLE 5.1 Deep Audit — ContextPane Full-Repository Architecture, Integrity & Frontier Blueprint

**Audited commit:** `3ea7563` (main, clean tree at start) · **Date:** 2026-10-28 · **Auditor:** Claude Fable 5.1 (six parallel forensic passes + independent line-level verification + live 1440×900 session against the user's running orchestrator in Real-Tenant mode)

**Method.** Every finding below was read in source and cites `path:Lstart-Lend`. Agent findings were not accepted on trust: every CRITICAL row and a sample of every HIGH row was re-opened and re-read by the lead auditor. Live claims come from the running stack (`/api/health`: `liveCloudMode: true`, `dataMode: real-tenant`, Meta key present, Modal sandbox and Glimmer endpoint configured) in the in-app browser at a 1440×900 viewport. Evidence screenshots are in `docs/fable-research/evidence/`. Typecheck and the 200-test offline suite pass (`bun test`: 200 pass / 0 fail / 28 files).

**One-paragraph verdict.** ContextPane has a genuinely strong spine: real MCP-shaped tenant services with live Graph/ARM paths, real `muse-spark-1.3` / `muse-wonder-1.0` / `muse-voice-transcribe-1.0` tool-forced calls with honest router telemetry, a real Modal sandbox, real git staging, a real Glimmer-30B llama.cpp deployment, and a lens/hover/clarifier operator surface that no competitor at this hackathon will match. But the layer between that spine and the screen still contains **nine CRITICAL "demo theater" paths** that a judge or a cloud architect would catch inside the 3-minute demo: a catch-all that stamps *Verified Safe* with invented timings, a custom-ticket approval that records *executed live · HTTP 200* without calling any API, a client-side "Auto-Fix" that flips every invariant to passed, a 5-sub-agent pipeline whose clarifier answers never reach the coder at triage (the persisted proof chose *Recover the old vault* and got a purge script), 270 of 274 "synthesized" catalog entries that are a deterministic template stamped `muse-wonder-1.0`, and a landing page that says **Dashboard** eleven times to a jury that was told to skip dashboards. All nine are surgical fixes (most under 20 lines). The frontier upgrades in Section 4 are deliberately scoped so that the fix pass and the wow pass fit in the same two-day window before recording.

### 3.5 Popover pinning (static analysis, corroborated by live selection test)

Selecting text inside a portal popover and clicking *Generate Context UI* works on the happy path (`SelectionTrigger.tsx:L240 onMouseDown preventDefault`, `EntityPill.tsx:L125-L128 outsidePress` excludes the bar). Three races remain: (1) floating-ui `pointerdown` fires before SelectionTrigger's `mousedown`, so an outside click while a bar is up leaves the popover open until a second click (`EntityPill.tsx:L100-L105` vs `SelectionTrigger.tsx:L141-L149`); (2) a drag that ends outside the popover closes it after the 180 ms hover-close before `mouseup` (`EntityPill.tsx:L83-L110`); (3) any selection bar anywhere pins every open popover. Fix: a `selecting` flag set on `pointerdown` inside the popover and cleared on document `pointerup`, and re-arm the close check when the bar unmounts (custom event). Live note: my first synthetic `Generate` click dismissed the bar without firing the request; a native double-click selection then worked, so the race is real but narrow.
